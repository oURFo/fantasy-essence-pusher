# 秘境金庫 — 網頁推幣機原型

## 啟動

需要 Node.js 22.18 以上（目前使用 24）。

```powershell
npm install
npm run dev
```

開啟終端顯示的本機網址（通常為 http://127.0.0.1:5173）。不可直接雙擊 HTML，因物理引擎需經 HTTP 載入。

- 按「投下一枚精華」或空白鍵投珠。
- 出幣口自動左右移動，精華從按下當下的位置釋放。
- 針陣使用實際碰撞；下方推板自動往復。
- 前方掉落完成後計數，左右側牆封閉，不設側邊回收口。
- 出幣口速度固定，玩家介面不提供重置；切到其他分頁自動暫停。

## 模組

- src/main.ts：初始化、輸入、固定時間步與介面。
- src/config.ts：精華、針柱及模擬參數。
- src/physics.ts：Rapier 3D 精華碰撞、針板轉接、推板、回收與重置。
- src/rendering.ts：AI 圖像圖集、固定視角投影、前景遮擋。
- public/assets/：內建 imagegen 生成的機台和透明圖集。
- tests/physics.mjs：60 秒物理整合驗證。

## 驗證與打包

```powershell
node tests/physics.mjs
npm run build
```

dist 可部署到一般靜態網站空間。這次交付為本機原型，未建立正式線上站台。

## 現階段範圍

畫面使用 Canvas 2D 分層繪製 AI 素材，碰撞採 Rapier 3D；未使用 Three.js，可減少渲染開銷。機台、出幣口、推板、針柱及精華外觀皆來自 AI 圖片，可見機台並非幾何物件拼接。物理碰撞體不可見。

這是玩法與美術整合原型。固定視角投影和透明精華使用 AI 球形圖片呈現，高光與折射為繪製效果，也未完成長時間效能與手機裝置驗證。上方與下方物理空間連續，轉接處有前導板開口；針柱與側牆保留足夠通道，停滯精華由微幅針板震動解除平衡；已驗證連續 60 枚投珠皆通過針板。暫無商店、任務、存檔、付費或兌獎功能。




目前使用 Rapier 球體碰撞；綠色透明玻璃珠保持圓形輪廓，附接觸陰影。AI 素材：public/assets/green-bead.png。


精華物理材質改為高摩擦低彈性橡膠：摩擦係數 0.95、彈性 0.025，落入珠床後線性阻尼 1.8、旋轉阻尼 8；針板段維持較低阻尼，避免卡珠。


前方出口依有效檯面寬度分為左側 1/4 系統回收、中央 1/2 玩家獎勵、右側 1/4 系統回收。珠心離開前緣時鎖定區域，落下完成後結算；分界線上的珠心歸系統回收。


底部以 AI 寶箱場景取代分區文字：中央珠子落入寶箱開口，箱體前緣遮擋入箱珠，獎勵結算時點亮正中央寶石約 1.6 秒。左右為空的深色通道，珠子直接落底回收，不觸發亮光。


針板取消最後一排，換為七格：無獎勵／精華／無獎勵／大龍珠／無獎勵／精華／無獎勵。玩家精華每顆只判定一次；精華格從推台右側依序噴出兩顆精華，龍珠格從中央出珠口釋放一顆 1.5 倍直徑龍珠。補珠不連鎖觸發，容量不足時排隊補發；重置清除佇列。驗證：node tests/prize-slots.mjs。


出珠口更新：AI 龍頭取代中央一般出幣口，右側 AI 管口朝中央噴出精華。龍頭冠部、兩頰及管口上下緣有實體碰撞，補珠生成於出口外。龍頭下方四顆錯位針柱打斷直落中央獎勵格的路徑；未修改七格判定寬度。測試：node tests/outlets.mjs。

## SLOT（初版配獎）

背板中央嵌入 AI 框體與九種符號圖集的三軸一線 SLOT，針板維持在螢幕前方，以免出現不可見碰撞。大龍珠從中央寶箱落下完成後啟動一次，左右系統回收不觸發；普通精華不觸發。

|三個相同圖示|精華|機率|
|---|---:|---:|
|翠葉|10|30%|
|藥水|15|24%|
|水晶|20|18%|
|盾牌|30|12%|
|寶劍|40|8%|
|卷軸|50|5%|
|寶箱|100|2%|
|王冠|200|0.8%|
|金龍|300|0.2%|

每次必得，平均 23.7 顆。先依上表權重抽定獎項，再以三軸相同圖示呈現；並非三軸獨立抽樣後判定連線。三軸於 2、2.7、3.4 秒依序停止，最短結果顯示 1.5 秒；右側管口約每秒 5 顆派珠，派完後才開始排隊中的下一轉。珠床滿時保留獎勵等待派送。最高 300 顆需要約 60 秒出珠，不會一次生成而重疊。

src/slot.ts 為獎項與狀態機；src/slot-rendering.ts 為動畫；tests/slot.mjs 驗證權重與整合配獎。圖框與符號使用內建 image_gen.imagegen，原始提示詞保存在 public/assets/slot-*-prompt.txt。

防柱頂卡珠：針柱改為非對稱凸稜柱，上緣約 29 度斜面、左右交替；針柱摩擦 0.025（Min 合併），珠床橡膠摩擦保留。罕見多珠橋接超過 0.65 秒未向下進展時施加按質量縮放的小幅震動。AI 導流柱素材：deflector-peg.png。tests/anti-stall.mjs 驗證 32 組正中柱頂落下，0.6 秒內滑離，並測試連續精華與龍珠；700 次投放皆通過，龍珠格樣本比例 7%。



頂部跑馬燈：使用既有 AI 框體，顯示待機、SLOT 旋轉中與中獎精華數。10～50 精華為淡綠色輕微開獎燈效；100（含）以上，即100/200/300，為較強金色邊燈與粒子，持續約3.2秒。燈效於正式開獎後觸發，自動結束並支援減少動態效果。tests/celebration.mjs 驗證含100門檻、訊息、重置與燈效時序。


最新調整：針柱恢復圓形外觀與圓柱碰撞，接觸面維持低摩擦；0.35 秒未向下前進時觸發按質量縮放的微震動，讓精華與龍珠離開柱頂。32 組正中柱頂測試皆在 1.5 秒內釋放。精華出珠初速每顆獨立隨機取原本1～2倍（向左3.2～6.4），五個代表力道空台落點x為1.75、1.48、1.22、0.96、0.69；tests/ejection.mjs驗證。700次投放全通過，龍珠格樣本比例8.57%。


精華出口改為左右雙側，兩側均朝中央噴射；所有七格與 SLOT 獎勵共用『左、右、左、右』逐顆交替順序，間隔至少0.18秒，並保留1～2倍隨機力道。滿台等待不跳號，重置後從左側開始。tests/alternating-outlets.mjs 驗證。


最新派珠：全域左右交替間隔縮短至0.08秒（60Hz下約0.083秒），SLOT得獎精華立即排入連續佇列，取消逐批到期等待。場上容量由240提高至600，容納初始108加最大300獎勵。300顆實際物理派珠測試24.92秒完成、最大間隔0.083秒。前緣中央加入寬0.36、高0.42的小三角分珠柱（AI素材44×42顯示），尖端朝機台內，以低摩擦實體稜柱偏折精華。驗證：tests/continuous-ejection.mjs。


最新平衡（已更正）：龍珠格命中後必出一顆，取消命中後的二次抽選；透過最下排兩根針柱由x=±1.35移至±1.2降低進格率。精華格與SLOT獎項機率不變。三角分珠柱寬、深、高及AI素材顯示尺寸同步乘1.6。tests/dragon-rate.mjs 驗證命中必出，並以相同3500次投放比較調整前後針陣。

## 第二機台：空之翼

大廳第二台天空推珠機，三階段為浮島初翼、蒼穹展翼（300 秒）、天域聖翼（100 秒）。獎勵格觸發八格加權輪盤；翅膀總權重基本 3%、二階 1.5%，升階與返航時停止玩家投入，先結算原檯面的輪盤、派珠與上方落珠，再持續運作十秒後換階。中央二分之一掉落返幣，左右各四分之一回收。規格見《空之翼設計規格.md》。

規則：src/sky-rules.ts；物理整合：src/sky-game.ts；AI 素材與演出：src/sky-rendering.ts、public/assets/sky-wings/。執行 node tests/sky-wings.mjs 與 node tests/sky-physics.mjs 驗證。三階機殼、輪盤、羽翼為內建 imagegen 製作，提示詞與用途記錄於 public/assets/sky-wings/ARTWORK.md。

### 空之翼效能優化（2026-10-21）

主要瓶頸為每顆珠子每幀的 Canvas 變色濾鏡及高解析素材縮放，另有排序比較時重複呼叫 Rapier WASM 讀取座標。現在先建立三階材質與背景快取，球體貼圖為 96×96；背景、收集槽、輪盤、推板與噴口不再每幀重新調色。每顆珠子每幀只讀一次座標，裁切也改為整批一次。快取固定三組，估計額外像素緩衝約 21 MB，不隨珠數增長。側欄狀態改為每秒最多更新 10 次，操作事件仍即時更新；物理仍每秒 60 步。

同一台本機內嵌瀏覽器、1024×1536 畫布測試（8 幀暖身後取 40 幀；先讓物理運作 120 步再固定場景）：

| 實際珠數／階段 | 優化前繪圖呼叫平均 | 優化後 | 畫面間隔 P95 前 → 後 |
|---|---:|---:|---:|
| 98／基本 | 2.30 ms | 0.61 ms | 100.1 → 16.8 ms |
| 256／青藍 | 5.39 ms | 0.82 ms | 133.5 → 16.8 ms |
| 514／金色 | 9.69 ms | 1.16 ms | 283.3 → 16.8 ms |

高珠量物理步驟平均約 1.6 ms，主要卡頓來自繪圖與瀏覽器的濾鏡合成。以上為受控固定場景的 CPU 繪圖呼叫與 rAF 間隔比較，並非所有裝置的完整遊戲 FPS 保證。量測原始資料見 `tests/sky-performance-results.json`；本機重測開啟 `tests/sky-performance.html`，優化前基準 commit 為 `2038d94`。Canvas 快取使用原 AI 素材，外觀與物理參數不變。

`tests/sky-draw-order.mjs` 驗證 600 顆珠子只有 600 次座標讀取，並保留原深度排序與前緣掉落層級。2,100 顆單珠及 2,880 顆連續投入的格位分布與優化前逐格相同。

#### 手動版本的機率與 RTP

現在落點由玩家力道、初速與實際碰撞決定，**不再加權抽選目標，也不播放預先選好的路徑**。因此初版固定權重的 95.33% RTP 不再是手動版本的遊玩保證；固定弱力、固定強力、均勻變化力道及玩家針對配方選擇力道，都會形成不同分布。fruit-economy.mjs 仍作為名目獨立權重的配獎模型驗證，不代表手動遊玩的實測 RTP。

以 200,000 次均勻分層力道投球校準固定感應口位置／寬度後，再換獨立種子測試 200,000 次均勻力道，三水果格實測 4.3785%、4.4925%、4.5205%、4.6560%；十二個雙水果格為 6.7745%～6.8920%。名目參考目標分別為 4.35%、4.45%、4.55%、4.65% 與 6.76%～6.92%，16 個目標互異、總和 100%。上述只適用於指定力道取樣政策，任意玩家操作不保證落在同一範圍。

驗證資料：tests/fruit-manual-physics-results.json。tests/fruit-manual-physics.mjs 測試全部 16 口可達、200,000 次參考投球維持 4～5%／6～7% 區間，以及弱力／強力實際落點有明顯差異。tests/calibrate-fruit-board.mjs 是離線重算幾何的工具，遊戲不在開局時重新校準或更改機率。原 fruit-paths.mjs 測試入口已改為呼叫即時物理驗證，舊快取路徑模組已移除。fruit-game.mjs 另驗證不自動發射、最多 16 顆、鍵盤蓄力與取消、同軌道不重複裝填、結算只入帳一次。

感應口會對每一次向下穿越做判定，包含彈珠反彈回到同一排後再次下降；不會只判第一次通過。離線校準亦使用完整穿越歷程，以免反彈路徑造成機率偏差。

### 投擲與套中

按住底部圈圈，左右選出手位置，同一手勢下拉決定力道，放開投出。行動裝置使用 pointer capture / touch-action:none，取消、失焦與離場確認不誤發射。鍵盤聚焦出手區後左右選位、上下微調拉動幅度（Shift 更細）、Enter 或空白投出；不顯示力道百分比。

使用場地 x/z 與高度 y 的簡化圈圈物理，120Hz 更新、重力與地面摩擦、瓶身圓柱及圈圈內外徑碰撞。每次出手抽一次均勻 -2°～+2° 風偏，以初始側向速度作用，飛行途中不重新抽選，也不抽中獎機率。下降穿越目標頂部時插值檢查內徑是否完整包住目標，擦邊彈跳；通過後需落到底部並穩定至少0.3秒才取得一件。這是水平圈圈加圓柱的簡化物理，未模擬可自由翻倒的剛體圈或獎品傾倒。

同時最多一圈飛行，套中後短暫顯示圈圈與獎品發亮，再播放獎品飛入背包、移除圈圈；未中圈在停下後移除。目標不消失、可重複套中，同一圈最多獲得一件。

### 背包與離場

套中先增加背包，金幣不增加。單項賣出售出該款所有數量，全部賣出售出整包，之後才寫入共用錢包。返回大廳先顯示確認，列出背包件數、售價及剩餘圈數；取消保留遊戲，確認離開自動售出背包一次、清除剩餘圈圈與飛行中的圈圈。重新進入機台為空背包、零圈圈。購買與離場不退圈款。
